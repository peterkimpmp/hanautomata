# macos — 한오토마타 macOS 입력기 0.6.1

InputMethodKit 입력기다. 판별·조합·학습은 Rust 공통 엔진([core](../core/README.md))이 맡는다. 엔진은 UniFFI 계층([ffi](../ffi/src/lib.rs))을 거쳐 Swift 셸과 연결된다. Windows 트레이 앱과 같은 판별 결과를 낸다(동등성 게이트 G1).

기능 정의서(공통 C · macOS M ID)의 macOS MVP와 1.0 기능을 코드와 자동 검사로 구현했다. 실물 키보드와 실제 앱에서 확인하는 호환 스위트(G2)는 [COMPATIBILITY.md](COMPATIBILITY.md)의 점검표로 진행한다.

## 빌드·설치·제거

```sh
cd macos
./build.sh --test       # Rust 엔진 검사 + Swift 키 매핑·엔진 연결·입력 로직 검사 → build/Hanautomata.app (이 Mac 아키텍처)
./build.sh --universal  # Apple Silicon + Intel 한 묶음
./install.sh            # ~/Library/Input Methods에 설치(관리자 권한 없음), 입력 소스 등록, 전환 키와 겹치는 macOS 설정 점검
./uninstall.sh          # 입력 소스를 끄고 앱을 지운다. 학습 파일은 남긴다
./package.sh            # 출시 묶음: universal zip + SHA-256 + Homebrew cask(build/dist/). 올리거나 게시하지 않는다
./package.sh --with-proofreading # 기존 실험 맞춤법 검사기·사전·소스·고지를 함께 담는 universal 묶음
```

- **처음 설치 때 한 번 직접 추가해야 한다.** 시스템 설정 → 키보드 → 입력 소스 → 편집… → + → 한국어 → 한오토마타 순서로 추가한다. macOS 26에서 `TISEnableInputSource`가 성공을 돌려줘도 실제로 켜지지 않는 것을 확인했다(2026-10-11). `install.sh`는 실제 상태를 보고, 켜지지 않았으면 이 안내를 출력한다.
- **다시 설치한 뒤** 옛 판으로 입력하던 앱은 입력 소스를 한 번 바꿨다가 되돌린다(그래도 안 되면 앱을 다시 연다). 입력기 프로세스가 바뀌어도 열려 있던 앱은 저절로 다시 연결하지 않았다(2026-10-12).
- **전환 키와 겹치는 macOS 설정**은 `install.sh`(내부적으로 `Hanautomata --check`)와 첫 실행 설정이 읽어서 알려 준다. 바꾸지는 않는다.
  - 키보드 단축키 '입력 메뉴에서 이전/다음 소스 선택'이 ⇧Space면 ⇧Space가 한오토마타까지 오지 않는다.
  - 'Caps Lock 키로 ABC 입력 소스 전환'이 켜져 있으면 시스템이 Caps Lock을 먼저 가져간다.
- 메뉴 막대에서 고정 모드 아이콘(가·A)을 보려면 '한오토마타 (한글 고정)'·'한오토마타 (영문 고정)'도 추가한다. 추가하지 않아도 모드는 바뀌고 입력 메뉴에 표시된다.
- 필요한 것: Xcode Command Line Tools(swiftc), Rust 1.89+(cargo). universal 빌드는 `rustup target add x86_64-apple-darwin`이 필요하다. 내 표현 서비스도 같은 아키텍처로 빌드해 앱 안에 포함한다.

개발판 입력 메뉴의 **내 표현…**에서 직접 등록한 표현을 찾아 복사할 수 있습니다. 별도로 창만 열려면 `build/Hanautomata.app/Contents/MacOS/Hanautomata --personal-expressions`를 실행합니다. 이 방식은 입력기 등록 없이 동작하며, 입력 중 자동 추천과 LLM 기능은 아직 포함하지 않습니다. [MVP 명세](../docs/specs/PERSONAL-ASSIST-MVP.md), [검증 상태](../docs/PERSONAL-ASSIST-VALIDATION.md)를 참조하세요.
- 파일은 모두 `~/Library/Application Support/Hanautomata/`에 있다. 입력기 프로세스 하나만 쓴다(C-OPS-09).

| 파일 | 내용 |
|---|---|
| `words.json` | 학습 파일. Windows 트레이 앱과 같은 문서 형식(Format 2) |
| `keep.txt` · `convert.txt` | 예외 목록(안 바꿀 단어 · 항상 바꿀 단어). 한 줄에 하나, `#` 설명. 고치면 다음 입력부터 반영 |
| `diagnostics.json` | 진단 집계. 글자 없이 횟수만(`Hanautomata --diagnose`, `--diagnose reset`) |

## 자동 띄어쓰기 (0.6.1)

Windows 트레이의 14개 닫힌 규칙을 Rust로 이식했다. `할수있다 → 할 수 있다`, `하는것 → 하는 것`처럼 공백만 넣는다. 전체 문장 문법 검사나 통계 모델은 아니다. 조합 밑줄은 보존하고 후보창에 확정될 글자를 미리 보여 주며, Space·Enter·Tab·단축키·포커스 이동 시 확정문에 적용한다.

입력 메뉴와 설정 → 입력의 **자동 띄어쓰기**(기본 켬)에서 끌 수 있다. Space 확정 직후 15초 안에 후보 바꾸기 키(기본 F2)를 누르면 같은 입력 칸·커서·원문인지 읽어 확인하고 원문으로 되돌린다. 이때 학습하지 않는다. 한 번 더 누르면 기존 언어 재변환이다. 복원한 표현은 프로세스 메모리 256개 안에서만 제외하며 디스크에 저장하지 않는다. 보안 입력과 제외 앱에는 적용하지 않는다.

[규칙 상세](../docs/SPACING.md), [macOS 0.6.1 검증 기록](SPACING-VALIDATION.md). Windows 메모장의 지연 전송은 macOS에 넣지 않았다. IMK의 `insertText`로 확정문을 한 번 전달한다.

## 서명·배포 (M-14 · 결정 D15)

- 2026-10-16: Developer ID 구매를 사용자가 검토하고 있다. 0.5.0 사전 공개본은 ad-hoc 서명이다.
- zip에는 앱·고지 4종·`Install.command`·`README.txt`가 들어 있다. `--with-proofreading`이면 검사기와 사전·정확한 소스·고지도 앱 안에 서명 전에 넣는다. 입력기와 검사기 모두 Apple Silicon·Intel 바이너리를 포함한다.
- 설치기는 새 앱의 서명과 복사본을 확인한 뒤 기존 앱을 `~/Library/Application Support/Hanautomata/Backups/`로 옮겨 보관한다. 교체 실패 시 복구하며, 이전 입력기가 종료되지 않으면 교체하지 않는다. 기존 맞춤법 검사 기능을 빼는 갱신은 거부한다. 학습 파일과 설정은 건드리지 않는다.
- 기본은 ad-hoc 서명이다. 내려받은 zip은 Gatekeeper가 막을 수 있다. 출처와 SHA-256을 확인한 뒤 시스템 설정 → 개인정보 보호 및 보안에서 **Hanautomata의 확인 없이 열기**를 선택한다. 현재 공증 여부는 검증 기록에 적는다.
- Developer ID가 생기면 다음 두 변수를 두고 `./package.sh`를 실행한다. 그러면 hardened runtime으로 서명하고, 공증한 뒤 티켓을 붙인다.
  - `HANAUTOMATA_SIGN_ID="Developer ID Application: …"`
  - `HANAUTOMATA_NOTARY_PROFILE=<notarytool store-credentials 프로필>`
- Homebrew cask 초안은 `Packaging/hanautomata.rb.in`이다. `package.sh`가 판 번호와 체크섬을 채워 `build/dist/hanautomata.rb`를 만든다. tap에 올리는 일은 별도 출시 단계다.

### 아직 하지 않은 것

| 항목 | 이유 |
|---|---|
| 입력 칸 종류 반영(C-DET-07) | **macOS 해당 없음(결정 D21 · 2026-10-12).** InputMethodKit에는 입력 칸 종류를 알려 주는 공개 경로가 없다. 손쉬운 사용 정보로도 웹·네이티브 칸의 URL·이메일·숫자 구분은 나오지 않는다 [I](검색 칸은 C-CTX-07에서 쓴다). 비밀번호 칸은 OS가 입력 소스를 바꿔 처리한다. Windows는 InputScope로 구현한다(W-09) |
| 검색 칸 즉시 반영(C-CTX-07)의 실물 확인 | 코드와 자동 검사는 끝났다(위 1.0 표). Safari·Finder·Chrome 검색 칸에서 첫 음절부터 결과가 바뀌는지, Esc 취소·재판별이 보존되는지는 손쉬운 사용 권한을 준 뒤 실물로 본다 |
| Office·한컴 자동 고침과의 이중 변환(C-CTX-05) | 호환 스위트에서 '자동 고침 끔' 상태를 지원 조건으로 두고, 켬 상태의 결과를 기록한다 |
| 시스템 표시기(M-10)의 실제 표시 | 모드를 입력 모드로 노출했다. 메뉴 막대·커서 옆 표시가 실제로 바뀌는지는 실물 확인이 필요하다 |

## 결정이 필요한 것

- **커서 앞 문맥 기본값(C-DET-08)**: held-out 측정 결과는 아래와 같다. 정의서 인수 기준은 '혼용 문장에서 오변환 증가 0'이다. 이를 넘지 못해 기본값을 껐다.

  | 앞 문장 | 한글 단어 놓침(1,000개 중) | 영어 단어 오변환(1,000개 중) |
  |---|---:|---:|
  | 없음(현행) | 15 | 0 |
  | 같은 언어 | 6 | 0 |
  | 반대 언어 | 15 | 4 |
