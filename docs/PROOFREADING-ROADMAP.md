# Hanautomata 맞춤법은 독립 로컬 검사기부터 단계적으로 제공한다

- CLI·분리 프로세스·선택문 UI·호스트 어댑터를 구현했다.
- 기존 키 입력 경로와 맞춤법 처리의 지연·오류를 분리한다.
- 교정은 제안하며, 적용 시 원문과 문서 상태를 다시 확인한다.
- 79개 개발 예문의 top-3와 오류문 지연은 승격 목표에 미달했다.

**결정:** 선택한 한국어 텍스트에 대한 로컬 표기 후보를 명시적으로 실행하는 실험 기능으로 제공한다. 기본 배포에 자동 활성화하지 않는다. 계정이 필요한 말뭉치 없이 빌드·실행하며, 품질 목표 미달을 이유로 정확도나 완료 기준을 낮추지 않는다.

근거는 2026-10-16 작성한 `20261016-deep-hanautomata-korean-proofreading-feasibility.md`와 `20261016-deep-korean-spellcheck-data-best-practices.md`다. 두 연구 노트의 결정 사항을 이 문서에 옮겼으며, 원본 노트가 없어도 공개 저장소를 빌드할 수 있게 한다. 기준 제품은 0.5.0 / `d6ad4ae`다.

```mermaid
flowchart LR
  A[M0 사전과 계약] --> B[M1 독립 검사 CLI]
  B --> C[M2 선택 영역 제안 UI]
  C --> D[M3 TSF와 macOS 연결]
  B --> E[M4 문맥·띄어쓰기 비교]
  E --> C
```

## 1. 범위와 완료 조건

| 단계 | 산출물 | 완료 조건 | 선행 조건 |
|---|---|---|---|
| M0 데이터·서비스 계약 | 버전·SHA-256·고지, 오프라인 로더, JSON 진단 형식 | 공개 자산만으로 재현; 손상·누락 사전은 명시적 실패; 원문·UTF-8·UTF-16 범위 일치 | 없음 |
| M1 첫 실행 증분 | 독립 Rust 검사 라이브러리·CLI, 보호어, 테스트, 사용 안내 | 실제 한국어 사전에서 후보 생성; 정상·보호 대상·NFD·이모지 회귀 통과; 지연과 한계 기록 | M0 |
| M2 선택 영역 UI | 검사·제안·사용자 선택·다시 검사, 비동기 작업 프로세스 | 오래된 요청·다른 문서·변한 원문에 적용 0건; 앱 종료·작업 취소 복구; 텍스트 로그 없음 | M1 및 UI 연결 전용 평가 |
| M3 호스트 연결 | Windows 트레이 → TSF → macOS 어댑터 순차 적용 | 각 대상 앱에서 선택·교체·되돌리기·포커스·조합 중 보호 확인; 기존 입력 회귀 유지 | M2; 기존 플랫폼 인수 게이트 |
| M4 문맥 확장 | Kiwi 비교, 근거가 있는 규칙, 띄어쓰기 후보 | 동일 고정 평가셋에서 오탐·후보 적중·지연·메모리 비교 후 채택; 개선 없는 구성은 제외 | M1 평가 파이프라인 |

2026-10-16 후속 지시에 따라 이번 개발 범위를 M0~M4 전체로 확장했다. 구현과 자동 검증을 끝까지 진행하되, 실호스트 인수와 품질 목표는 실행 증거가 있는 경우에만 통과로 표시한다. 단어가 사전에 없다는 결과는 `unknown_word`로 표시하고, 비표준어 또는 명백한 오류로 확정하지 않는다.

### 전체 구현 작업 순서

1. 별도 프로세스 감독기: JSONL, 요청 식별, 취소·시간 제한·자원 제한·재시작을 먼저 테스트한다.
2. 원문 스냅샷을 보존하는 선택 영역 UI와 호스트 계약을 구현한다. 자동 수정은 하지 않는다.
3. macOS IMK, Windows 트레이 및 TSF 진입점을 연결하고 플랫폼별로 빌드·회귀 검증한다.
4. 직접 작성한 고정 평가셋으로 사전 단독·근거 규칙·Kiwi를 같은 조건에서 비교한다.
5. 빌드 산출물·사전·대응 소스·고지를 확인하고 실행 증거와 남은 인수 조건을 기록한다.

Windows 365는 사용자가 지정한 aside 원격 호스트에서 시험한다. 독립적으로 사람이 검수한 정상문 1,000건은 아직 확보하지 못했다. 합성 문장 수로 검수 표본 수를 대체하지 않는다.

개발 공수의 초기 가정은 M0~M1 3~5 개발일, M2 5~8일, M3 플랫폼별 5~10일, M4 비교 실험 5~10일이다. 이는 개발자 1명의 계획 추정이며 약속된 일정이나 이번 작업의 소요 시간을 뜻하지 않는다. 게이트 실패·플랫폼 접근성에 따라 재추정한다.

## 2. 구조와 인터페이스

검사기는 `core/tools/proofread/`의 독립 crate다. `core`, `ffi`, TSF에 네이티브 검사기를 링크하지 않는다. M2에서 구현한 JSONL 감독 프로세스가 별도 네이티브 자식을 관리하며, 취소·요청 대체·시간 초과 시 자식을 종료하고 회수한다. 문서·선택·요청 식별자는 호스트가 관리한다.

검사 입력은 확정된 텍스트 스냅샷과 사용자가 지정한 보호어다. 출력은 원문 범위, 원래 어절, 정규화된 검사 표현, 후보, 진단 유형, 검사·생략 건수, 제한 도달 여부다. 원문 전체를 정규화하거나 수정하지 않는다. 영어 혼용·URL·전자우편·코드·숫자 등 초기 검사기가 충분히 해석하지 못하는 구간은 보수적으로 생략한다.

첫 실행 엔진은 **Hunspell 1.7.1**이다. `hunspell-rs 0.4.0` / `hunspell-sys 0.3.1`에 포함된 C++ 소스를 빌드하고, 한국어 사전 0.7.94를 별도 파일로 읽는다. 빌드에는 C++ 컴파일러와 libclang이 필요하며 실행에는 설치된 Hunspell 서비스가 필요하지 않다. `Lexicon` 인터페이스로 후속 엔진을 비교할 수 있다. [Rust 래퍼](https://github.com/drahnr/hunspell-rs), [번들 빌드](https://github.com/euclio/hunspell-sys/tree/v0.3.1), [한국어 사전](https://github.com/spellcheck-ko/hunspell-dict-ko/releases/tag/0.7.94).

Pure Rust 후보 Spellbook 0.4.2는 실제 사전 실험에서 `돼요`, `학교에`, `먹었습니다` 등 정상 활용형을 거부하여 채택을 보류했다. 이것은 관측한 버전·사전 조합의 결과이며 일반적인 엔진 순위가 아니다. 이 실패 때문에 문서상 호환성을 실제 한국어 검사로 확인하는 게이트를 유지한다.

## 3. 데이터와 라이선스

| 자산 | 기본 정책 | 검증·공개 범위 |
|---|---|---|
| 한국어 실행 사전 | 버전·해시 고정, 별도 다운로드, 고지 보존 | 원본 아카이브·사전 파일 해시, GPL-3 고지, 대응 소스 좌표 |
| 자체 회귀 예문 | 직접 작성한 최소 예문과 정상 반례 | MIT, 출처·목적 명시; 실사용 로그 수집 없음 |
| 국립국어원 규범 | 새 규칙의 근거로 참조 | 규칙별 근거 링크·범위·정상 반례 |
| 신청형 말뭉치 | 기본 빌드·공개 CI에 넣지 않음 | 별도 승인된 평가 환경에서만 취급 |
| Kiwi 모델 | 0.24.0을 별도 평가 환경에서 비교; 제품에는 미포함 | 원시 띄어쓰기 기준선의 오탐과 메모리 때문에 현재 경로에 채택하지 않음 |

무료 배포여도 구성 요소의 의무는 남는다. MIT는 Hanautomata 자체 코드의 조건이다. Hunspell의 MPL-1.1 선택, Rust 래퍼 Apache-2.0, 한국어 사전 GPL-3 고지를 각각 유지한다. 공개 바이너리 배포 전에는 해당 의존성 소스·고지와 사전의 대응 소스 제공 절차를 패키지 단위로 검증한다. [사전 라이선스](https://github.com/spellcheck-ko/hunspell-dict-ko/blob/0.7.94/LICENSE.md).

## 4. 품질 게이트

첫 자동 회귀는 정확도 순위가 아니라 계약을 검증한다. 정상문 무진단, 보호어 불변, 코드·URL 생략, NFD 한글의 원문 범위, 이모지 뒤 UTF-16 위치, 손상 사전, 입력 상한, 후보 수 제한, 오래된 스냅샷 거부를 포함한다.

제품 후보의 품질 평가는 별도 고정 평가셋으로 수행한다. 원문 그룹 단위 분할과 복수 정답을 보존하고, 정상문 오탐률·오류 탐지 재현율·후보 top-1/top-3 적중률·생략률을 함께 보고한다. PC 두벌식·혼용문·고유명사·문체·띄어쓰기를 나누며, 전체 점수로 취약 구간을 숨기지 않는다.

일반 사용자 기능으로 승격하기 위한 목표는 독립 검수 정상 1,000문장의 문장 오탐률 1% 이하, 고정 오타셋 top-3 80% 이상, 300자 warm p95 300ms 이하, 원문/범위/보호대상 훼손 0건이다. 실험 UI 구현은 이 승격을 뜻하지 않는다. 현재 자체 예문 79건에서 규칙 포함 top-3는 68.97%, 오류 집중 300자 p95는 약 1.12초로 목표에 미달했다. 규칙 개발에 사용한 5건을 제외하면 오류 24건의 top-3는 62.5%다. [측정 방법과 한계](PROOFREADING-VALIDATION.md).

UI는 `--serve` 프로세스의 3초 기한과 512MiB 자원 예산을 사용한다. Windows는 Job Object의 프로세스 commit 제한, Linux는 RLIMIT_DATA, macOS는 5ms RSS 표본 감시를 사용한다. **macOS의 표본 감시는 순간 최대 메모리를 보장하는 hard cap이 아니다.** 단독 일회성 CLI에는 이 감독 정책이 적용되지 않는다.

## 5. 사용자 효용과 유지 가능성

선택문 복사·붙여넣기와 외부 전송을 줄이는 것이 제품 가치다. 운영 서버 없이 로컬에서 실행하고, 사전 갱신은 해시 변경·회귀 결과·라이선스 변경을 함께 검토한다. 사용자에게 필요 없는 문체 수정이나 과교정을 기본 기능에 넣지 않는다.

지표는 교정 후보 채택·오탐 제보·재현 가능한 빌드·회귀 실패·이슈 해결 시간을 중심으로 둔다. 수집은 동의한 최소 예문 기반이며 입력문 자동 수집을 전제하지 않는다. 유료 전환율과 서버 기반 사용량 과금은 프로젝트 목표가 아니다.

## 6. 구현 현황

| 단계 | 구현 현황 | 인수 판정 |
|---|---|---|
| M0 | 고정 사전·원천 소스·고지·해시·JSON 계약 | 로컬 재현·손상 거부 검증 완료 |
| M1 | 보수적 어절 검사·보호어·UTF-8/16 범위·CLI | 계약·실사전 회귀 완료; 범용 정확도 승인은 아님 |
| M2 | JSONL 감독기·취소·기한·자식 회수·제안 UI | 자동 회귀 완료; 전체 UI 인수는 별도 |
| M3 | 트레이 제안 복사·TSF edit session·macOS IMK 어댑터·독립 검증용 편집기 | 빌드 및 보호 계약 검증; 실제 앱 전체 인수 미완료 |
| M4 | 정확 어절 5개 규칙·79건 고정 평가·Kiwi 비교 | 비교와 미채택 결정 완료; 정확도·성능 승격 게이트 미통과 |

Windows 트레이 UIA는 원자적으로 선택 영역을 교체할 수 없어 **사용자가 누르는 제안 복사만** 제공한다. 직접 적용은 TSF의 읽기/쓰기 edit session과 macOS IMK에 구현했다. 후속 요청으로 수행한 시스템 입력기 등록·사용자 설치 교체는 [설치 기록](PROOFREADING-INSTALLATION.md)에 따로 판정한다. 원격 CI 실행과 공개 릴리스는 여전히 미확인·미수행이다.

후속 승격 작업은 독립 검수 평가셋, 오류 밀도가 높은 문장의 후보 생성 최적화, 실제 앱별 포커스·조합·보호·단일 적용·실행취소 인수다. 실행법은 [PROOFREADING.md](PROOFREADING.md), 플랫폼별 증거는 [PROOFREADING-VALIDATION.md](PROOFREADING-VALIDATION.md)에 기록한다.
