## v0.4.1 자동 시작 보강 (2026-10-11 · 로컬 개발판)

사용자가 재부팅 후 자동 실행되지 않았다고 보고했습니다. 조사 시 기존 Run 명령은 설치 경로와 일치했고 해당 항목의 StartupApproved 차단 값과 앱 오류 이벤트는 없었습니다. 실행 중인 프로세스는 당일 수동 실행 명령이었습니다. 이전 버전에 시작 기록이 없어 **해당 재부팅의 실패 원인을 단정하지 않습니다.** 별도로 Windows에서 비활성화한 Run 항목을 앱이 켜짐으로 판단하는 결함을 격리 레지스트리로 재현했습니다.

자동 시작을 사용자별 Task Scheduler 로그인 작업으로 교체했습니다. 실행 계정·활성 상태·경로를 확인하고 15초 지연, 실패 시 1분 간격 최대 3회 재시도, 시작 진단 로그를 추가했습니다. [구조와 복구 절차](STARTUP.md)

첫 Windows 기능 검사는 101개 중 1개가 실패했습니다. 공개 모델에서 `rm/그`는 앞 단어의 통계 문맥만으로도 변환될 수 있어, 학습 비활성화 검사에 적합하지 않았습니다. 보호 어휘 `wbs`로 검사 토큰을 바꿔 학습 기능을 분리하고 공개 단어 목록·민감도 검사 5개를 추가했습니다. 확장 검사의 첫 시도는 외부 창으로 포커스가 이동해 중단됐으며 성공 근거에 포함하지 않았습니다. 다음 완료 실행에서 106개가 통과했습니다.

배포 점검에서는 옛 패키지 폴더의 잔여 파일이 ZIP에 섞이는 문제와, ZIP의 설치 스크립트가 `build/`에서 EXE를 찾는 문제를 재현하고 수정했습니다. 릴리스는 새 임시 폴더에서 패키징하며 검사한 EXE를 그대로 담습니다. ZIP 해시는 `SHA256SUMS.txt`, EXE 해시와 소스 커밋은 `release-manifest.json`에 있습니다. 이 메타데이터는 서명이나 암호학적 빌드 출처 증명을 대신하지 않습니다.

## 검증하지 않은 것

- 실물 PC(가상 PC·원격 데스크톱이 아닌)에서의 물리 키보드 입력과 Raw Input 감시의 실제 재설치.
- 브라우저·채팅·IDE 등 실제 앱 5종 이상에서의 최종 표시 결과.
- 서명된 배포본. 베타 빌드는 "알 수 없는 게시자" 경고가 납니다.
- 일반 문장 정확도 추정치. held-out 수치는 단어 단위 회귀 게이트이며 실사용 정확도가 아닙니다.
- 실제 Windows 로그오프 후 로그인. 자동 시작 레지스트리와 같은 `--background` 명령의 재실행까지만 확인했습니다.
- 서로 다른 컴파일러·러너에서 EXE가 바이트 단위로 같은지 여부. 로컬 검사본·설치본·ZIP의 동일성만 해시로 확인합니다.
