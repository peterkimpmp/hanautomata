# 기능 비교 — 세 가지 구성 (0.5.0)

세 구성은 같은 판별 규칙을 씁니다. 트레이 앱은 C# 엔진, 입력기(TSF)판과 macOS판은 Rust 엔진이며 두 엔진은 동등성 게이트(G1)로 같은 결과를 확인합니다. 기본값도 같습니다: 자동 판별, 민감도 표준(`balanced`), `;` 후보 전환 켬, 선택 기억 켬, ⇧Space·Caps Lock·오른쪽 전환 키·F12 켬, 음절 지우기·MS 겹자음 끔.

● 있음 · ◐ 일부 · – 없음 · 해당 없음은 그 OS 구조상 필요 없는 항목입니다. 동작 확인 범위는 이 표가 아니라 [Windows 검증 원장](WINDOWS-QUALITY-RESULTS.md)과 [macOS 점검표](../macos/COMPATIBILITY.md)가 정본입니다.

## 판단 메모

- **macOS에 옮기지 않은 Windows 수정.** 후보 1~20의 수정은 대부분 TSF 호스트 처리(이동 키 조합 종료, Word의 Space 전 조합, 공백·Tab 포함 선택 변환)로, Rust 엔진 밖에 있습니다. F2 재변환에서 "단어만 바꾸고 공백은 두기"는 InputMethodKit에 커서를 따로 옮기는 호출이 없어, 옮기면 커서가 공백 앞으로 가는 퇴행이 생깁니다. macOS는 단어와 공백을 함께 바꾸는 현재 방식을 유지합니다 [I: Mac Word의 자동 고침 상호작용은 미확인].
- **Windows 입력기판에 없는 macOS 기능.** 한자·예외 목록은 Rust 엔진에 있어 TSF 설정과 연결만 하면 됩니다. 앱 프로필·vi 모드·최근 세 단어는 macOS 셸 기능이라 Windows 셸에 새로 만들어야 합니다. 우선순위는 출시 후 정합니다.
